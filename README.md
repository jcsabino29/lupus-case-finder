# Lupus Case Finder

Find documented and likely-missed systemic lupus erythematosus (SLE) cases in
synthetic patient records, using diagnosis codes, lab and medication evidence,
negation-aware search over clinical notes, patient similarity and cited AI
summaries.

> **Synthetic data only.** Every patient in this project is generated by
> [Synthea](https://github.com/synthetichealth/synthea). No real patient data
> is stored, processed or accepted. See [Data handling](#data-handling).

## Status

Stage 0 (setup) is complete: an empty, designed app with the security baseline
and CI. Case-finding features arrive in later stages.

| Stage | Scope |
| --- | --- |
| 0. Setup | Repo, CI, design system, security headers, schemas and roles |
| 1. Foundation | Synthea data, Prisma models, de-identification, auth, audit log |
| 2. Case finding | Python extraction, coded and lab-based queries, hybrid search |
| 3. Similarity | Patient similarity and reranking |
| 4. RAG layer | Cited case summaries behind a PII check |
| 5. Evaluation | Recall/precision report, security tests, threat model |

## Stack

- **Web:** Next.js (App Router, TypeScript strict), Tailwind CSS v4, shadcn-style components
- **Data:** Supabase Postgres with pgvector; Prisma for typed queries
- **Worker:** Python batch job (scispaCy, medspaCy, Presidio in stage 2)
- **Hosting:** Vercel (web) and Supabase (database)

```
src/
  app/                 routes, layout, global design tokens (globals.css)
  components/          AppShell, SyntheticDataNotice
  components/ui/       Button, Card, Input, Badge
  lib/security/        CSP builder and security headers (+ tests)
  proxy.ts             per-request CSP nonce
prisma/schema.prisma   multi-schema Prisma config (protected, research)
supabase/
  config.toml          local Supabase config (hardened auth defaults)
  migrations/          SQL migrations: schemas, pgvector, least-privilege roles
  tests/               pgTAP tests for the access model
worker/                Python batch worker (package lcf_worker)
```

## Getting started

Requirements: Node 24+, Python 3.12+, and optionally the
[Supabase CLI](https://supabase.com/docs/guides/local-development) with Docker.

```bash
npm ci
cp .env.example .env.local   # fill in local values only
npm run dev                  # http://localhost:3000
```

Checks:

```bash
npm run lint && npm run typecheck && npm test && npm run build
npm run db:validate          # validate prisma/schema.prisma
```

Local database (requires Docker):

```bash
supabase start               # applies supabase/migrations
supabase test db             # runs the pgTAP access-model tests
```

Worker:

```bash
cd worker && python -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]" && ruff check . && pytest
```

## Data handling

This project treats synthetic records as if they were real PHI.

- **Synthetic only.** Data comes from Synthea. The worker refuses to run unless
  `LCF_DATA_SOURCE=synthea`. Real records must never be loaded, uploaded,
  pasted into issues, or sent to any AI service.
- **Nothing in git.** Generated patient files (`data/`, Synthea output, CSV,
  NDJSON, Parquet, dumps) and all `.env*` files are git-ignored. gitleaks scans
  every push for secrets.
- **Two schemas.** Identifiable records live in `protected`; researchers only
  ever query `research`, which holds de-identified records (names removed,
  dates shifted, random IDs). Neither schema is exposed through Supabase's
  public Data API.
- **Least privilege.** The app and worker connect through no-login group roles
  (`app_researcher`, `app_admin`, `ingest_worker`) with explicit grants and
  row-level security. The database owner account is used for migrations only.
- **AI on de-identified text only.** Only research-schema text can reach the
  hosted model, after a PII check (stage 4). Clinical notes are treated as data,
  never as instructions.
- **Audit and minimisation.** Admin access to full records is audit-logged;
  logs hold IDs and counts, never record text; groups smaller than 11 are
  suppressed in research views.
- **Not HIPAA-covered.** The hosted demo has no Business Associate Agreement
  and is not approved for PHI.
